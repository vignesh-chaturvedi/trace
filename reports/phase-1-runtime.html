01 What this phase changed

Phase 0's agent holds a conversation in memory and loops over it. Phase 1 inverts that: the log is the conversation, and every turn rebuilds its context from the log. Structurally the loop is still the same twenty lines. Everything that matters follows from where state lives.

That single inversion is what buys byte-identical replay, clean resume from a crash, and offline ablation. None of the three is bolted on afterwards; each falls out of the fact that nothing is held anywhere else.

The four invariants

  • The log is the session. Append-only JSONL, monotonic gapless seq, fsync on boundary events. Flat text so it stays greppable, diffable, tailable, and streamable into a training pipeline.
  • Context is a pure function of the log. build_context(events, cfg, upto) reads no clock, no environment, no filesystem.
  • The prefix never moves. System prompt, tool schemas, and AGENTS.md form a byte-stable region, protected by a build-failing lint.
  • Losing work is a bug, not an accident. A tool call is durable before it runs; an interrupted one is unknown, never blindly repeated.

02 Language: Rust

Chosen after weighing it against TypeScript, which the source manual's Phase 5 section is written in (AsyncIterable<Event>, createSession). Worth being precise about the reasoning, because the obvious argument is the wrong one.

Speed was not the reason The harness is I/O-bound. Wall time goes to model round trips (2–20 s) and subprocesses (tests, builds). Language choice does not move task latency, and any claim that it does should be treated with suspicion.

The three reasons that did hold up:

  • Phase 3 needs Landlock and seccomp. Native crates in Rust; a native-addon fight in Node.
  • Determinism becomes structural. The manual's named "silent killer" — tool schemas serialized from a hash map, same content, different bytes, zero cache hits — is a bug this codebase cannot express. See §4.
  • One static binary. 3.4 MB, no runtime to install.

Dependency posture

Nine runtime crates: serde, serde_json, toml, blake3, libc, thiserror, ureq, clap, anyhow. Notably no tokio and no reqwest: the loop is inherently sequential, parallel tools use scoped threads, and blocking I/O keeps async from colouring the purity boundaries that §4 depends on.

04 Design decisions, and why

Tool output is stored whole and truncated late

The log keeps the complete output of every command. The truncate_limit is applied when the context is built, not when the result is written.

Why: it makes the truncation limit a replay-time ablation. Change the limit, replay the same log, and you get a genuinely different context to measure — no re-run, no new API spend. It also means the log never discards something a later analysis wants. The manual warns that sessions balloon on disk; the answer is to compress at rest, never to truncate what you store.

Deterministic serialization is enforced by the type system

Tool schemas and tool-call arguments are built from a JsonValue type whose only map variant is a BTreeMap.

Why: the failure this prevents is invisible. Schemas serialized from a hash map produce identical content and different bytes every turn, so the provider cache never hits and nothing in the code looks wrong. A test can catch it; a type that cannot express the mistake means it never has to. There is also a test — 100 randomized key insertion orders — because the guarantee is worth pinning.

The reinforcement frame is derived, never logged

The objective-and-status frame is computed by build_context from the events themselves — turn count is a count of responses in the log, not a counter held in the runtime.

Why: it makes the ablation clean. If the frame were appended as an event, a session run with reinforce = on could never be replayed as though it were off — the frame would already be sitting in the trajectory being measured. Deriving it means one log answers both questions.

Compaction declares a replacement; it never deletes

A compaction event records a range, a summary, and a provenance hash of the events it stands in for. The events stay.

Why: compaction is lossy by definition, so the loss must be recoverable. Replay expands back to full fidelity, which makes compaction strategies an offline comparison rather than an expensive experiment — and lets Phase 4 train on the uncompacted trajectory even though inference ran compacted. The provenance hash means "replay restored the original" is a claim the log can settle rather than an assumption.

An interrupted tool call is UNKNOWN, and is never re-run

tool_call is written and fsynced before execution; tool_result is written after. On resume, a call with no matching result emits a recovery event instead of being repeated.

Why: rm -rf build/ twice is fine and git push twice is not, and the harness has no way to tell them apart. So it does not decide. It records what it knows and hands the model the job of re-establishing ground truth — the one actor in the loop that can actually go and look.

Checkpoints never touch HEAD, branches, or the index

Committing uses a scratch GIT_INDEX_FILE plus write-tree and commit-tree, storing the result under refs/trace/<session>/<seq>.

Why: a harness that quietly rewrites your index is worse than one that does not checkpoint at all. Rewind restores tracked files but deliberately does not delete ignored ones — that would take node_modules and build caches with it — and reports the drift instead.

Parallel results are recorded in call order, not completion order

A batch of concurrent tool calls is sorted back into the model's original order before anything is appended to the log.

Why: otherwise replaying a parallel batch depends on which thread happened to finish first, and determinism — the entire point of the phase — is gone.

Mid-file log damage is an error, not a repair

A torn final line is truncated and recovered. A line that fails to parse anywhere else fails loudly.

Why: truncating at mid-file damage would silently discard every valid event after it. A gap in seq is likewise fatal rather than tolerated: replay, recovery, and compaction provenance all assume gapless numbering, so a plausible-looking wrong answer is the worst possible outcome.

05 Bugs the tests caught

Both were real, and neither was visible by reading the code.

The log repair path corrupted the first event

When a crash cost only the trailing newline, the repair wrote it back through a handle opened with write(true) — which starts at offset 0. The terminator overwrote the first byte of event 1, turning a one-byte loss into a corrupt ledger.

Found by the exhaustive kill sweep, not by the targeted torn-write test. Fixed by using append mode. The lesson generalizes: the sweep found it because it tried every offset rather than a plausible one.

The doom-loop nudge hardcoded "3 times"

The message told the model it had repeated a command three times regardless of the configured loop_threshold — so a reconfigured harness would assert a number the model's own transcript contradicted.

Fixed by substituting the observed count. Trivial to fix, easy to ship, and exactly the kind of thing that quietly erodes a model's trust in its own context.

Two test bugs, worth recording

  • A provenance-tampering test mutated events[3] assuming it was a tool result; it was a tool_call, so the if let silently did nothing and the test asserted against unmodified data. Now it searches for a victim and fails if it finds none.
  • An "append-only growth" test failed correctly: between a tool_call and its result, the builder seals the gap with an unknown placeholder, so that context is not an extension of the previous one. Such a context is never sent — requests are only built at turn boundaries. The test now asserts the property where it actually applies.

08 What is not built

The Phase 0 measurement rig

The substrate Phase 1 wraps is here; the rig around it is not. Missing: the Harbor adapter, sweeps with 3 repeats, per-task result rows, and a committed bench/runs/ history. Until that exists, "score stayed flat" is unfalsifiable — which is the one claim this phase is supposed to be able to make.

Deliberately deferred

  • Editing tools. Phase 1 ships bash-only so that every tool added in Phase 2 carries a measured delta. The scheduler already classifies read/grep/ls and edit/write, so they slot in without rework.
  • A SQLite index. The rebuildable JSONL index answers the queries that exist today without a C dependency. Swap it when the query load justifies it.
  • A real tokenizer. The estimate only gates compaction and errs high; the provider's reported usage is ground truth, and both numbers are recorded per request so drift is measurable rather than suspected.

Recommended next

Backfill the Phase 0 rig before starting Phase 2. It is roughly two weeks, it unblocks the one exit criterion that is genuinely blocked, and every phase after this one is harder to justify without a baseline to move.
